# 日志系统：还没做的部分

> 这是一份临时文档。已经做完的部分（盖戳、多个去处、最近记录、日志文件、捕获、同一个错只记一次、崩溃包、隐私处理、测试把关、编辑器菜单、崩溃界面、收进 Unity 的崩溃目录）已从这里删掉，用法见 `Docs/手册/日志.md`。
> 下面每一项做完就删掉那一节；全部做完，删掉这份文件。

## 一、崩溃界面换成正式界面

崩溃界面已经做了（用法见 `Docs/手册/日志.md` 的"崩溃界面"），现在用 OnGUI 画。系统级场景和界面框架搬过来以后，换成正式的界面，只换 `CrashPromptView`，别的不动。

## 二、上传

把一个崩溃包的目录压成一个文件交出去。接收的一方用现成的服务，不自建；具体用哪家，做这一块时再定。上传前必须得到玩家同意：只发 `CrashUploadQueue.Approved()` 列出来的包（玩家在崩溃界面上点过"发送"的）。

## 三、在打出来的包里确认 Unity 崩溃目录的位置

收进 Unity 崩溃目录已经做了，按 Unity 文档写的位置 `%TEMP%\<公司名>\<产品名>\Crashes` 去找（`LogSystemSettings.UnityCrashDirectoryFor`）。还要在一个真的打出来的 Windows 包里让它崩一次，确认目录确实在那、崩溃包里确实带上了 `crash.dmp`。确认完删掉这一节。

## 四、每行带上 tick 和对象

"第几个 tick""哪个对象"、只放大某一个对象的监视名单、每个 tick 的行数预算。要等内核（tick、句柄、命令）搬过来。黑匣子、命令记录与重放也在那时做。

## 五、还要你定的事

**公司名和产品名。** 现在是 Unity 的默认值 `DefaultCompany` 和 `unity_game`，日志和崩溃包的目录由它们决定。要在 Player Settings 里改；改了之后目录会跟着变，旧目录里的文件留在原处。发售前定下来就行。
