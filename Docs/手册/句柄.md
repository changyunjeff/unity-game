# 句柄：怎么用

## 它是什么

句柄是对"表里某一行"的弱引用，由两个整数组成：槽位的下标和代数。写出来是 `#42.3`，意思是第 42 个槽位的第 3 代。

它不控制那一行的生死。行被删掉之后，那个槽位的代数加 1，所有指着它的旧句柄当场失效；拿着旧句柄的人下次去查，查到的是"没有了"，由他自己决定怎么办。

为什么不直接存对象的引用：一个东西被删了，别人手里的引用却还让它活着，它就成了看不见的僵尸。用句柄，删了就是删了。

三个类，各管一件事：

| 类 | 管什么 |
|---|---|
| `Handle` | 不分类型的句柄。分配器、走边记录、存档这类不关心"是哪种东西"的地方用 |
| `Handle<T>` | 带类型的句柄。业务代码用它 |
| `HandleAllocator` | 分配器：发句柄、收句柄、判断句柄还有没有效 |

## 空句柄

`Handle.Null` 不指向任何东西。它就是默认值，所以一个没赋过值的句柄字段天然是空的。

```csharp
Handle<Workshop> target = default;
if (target.IsNull) { … }
```

## 带类型的句柄

`Handle<T>` 里的 `T` 只是个标记，一般就是那一行的类型。不同 `T` 的句柄互不相干：

```csharp
Handle<Workshop> workshop = …;
Handle<Citizen> citizen = …;

workshop = citizen;          // 编译不过
if (workshop == citizen) …   // 编译不过
```

把作坊的句柄错传给要居民句柄的地方，在编译时就会被拦下。

要拿到底层的句柄用 `.Raw`。反过来，从底层句柄包成带类型的，只能明着写 `new Handle<Workshop>(raw)`，这是留给表的实现和存档用的口子，业务代码不该出现。

## 分配器的规则

```csharp
var allocator = new HandleAllocator();

Handle a = allocator.Allocate();     // #0.1
Handle b = allocator.Allocate();     // #1.1

allocator.Release(a);                // a 失效，0 号槽位空出来
allocator.IsAlive(a);                // false

Handle c = allocator.Allocate();     // #0.2：复用 0 号槽位，代数加 1
allocator.IsAlive(a);                // 仍然是 false：同一个槽位，已经是另一个东西了
```

1. 新槽位的代数从 1 起，0 留给空句柄。
2. 收回时代数立刻加 1。
3. 空出来的槽位优先复用，后收回的先用。先后是固定的，同样的操作永远发出同样的句柄。
4. 空句柄和已经失效的句柄是正常情况：`IsAlive` 返回 `false`，`Release` 返回 `false`，不抛异常。
5. 下标超出槽位数的句柄是程序错误，多半是把别处发的句柄拿到这里来了：抛异常。

分配器只管槽位和代数，不存数据。以后的表在它旁边按下标放自己的行：行在 `rows[handle.Index]`，行还在不在问 `allocator.IsAlive(handle)`。

遍历所有还在的：

```csharp
for (int i = 0; i < allocator.SlotCount; i++)
{
    if (allocator.TryGetHandleAt(i, out Handle handle))
    {
        …
    }
}
```

遍历的过程中不要分配或收回。

## 现在哪里在用

状态机里"这台状态机属于哪个对象"就是一个 `Handle`：走边的记录者拿到它，子机发给父机的消息里的 `Source` 也是它。

## 还没做的

存档时要把分配器的状态（每个槽位的代数、哪些空着、空槽的先后）一起存下来，读档之后旧句柄才继续有效。这一步等搬存档的时候做。
