# 日志：怎么用

## 打一行日志

每个模块先放一个分类，名字和模块名一致：

```csharp
private static readonly LogCategory LogSave = new LogCategory("Save");
```

然后：

```csharp
Log.Info(LogSave, "读档完成");
Log.Warning(LogSave, "存档版本比游戏旧，已升级");
Log.Error(LogSave, "读档失败：文件不存在");
Log.Verbose(LogSave, "读到第 " + index + " 张表");
```

在最外层接住了一个异常，用这个记下来，它会带上异常的调用栈：

```csharp
catch (IOException exception)
{
    Log.Exception(LogSave, exception, "写存档");
}
```

## 五个级别什么时候用

| 级别 | 什么时候用 |
|---|---|
| `Error` | 不该发生的事：断言没过、配置表有错 |
| `Warning` | 还能继续跑，但不正常 |
| `Info` | 生命周期：模块初始化、读档存档、状态切换 |
| `Verbose` | 细节：每条命令、某个对象的每次状态变化 |
| `VeryVerbose` | 最细：某个对象每一步的数值 |

- 一个分类默认只输出到 `Info`。要看更细的，调高那个分类：`LogSave.MaxLevel = LogLevel.Verbose;`
- `Verbose` 和 `VeryVerbose` 只在编辑器和开发版里存在，发布版里整句消失，可以放心写。
- 同一个错反复出现时，只在第 1、10、100、1000 次各记一行，行首会写"同一个错已重复 N 次"。

三条规矩：遍历大量数据的循环体里不打日志；日志语句不改游戏状态；除了 `UnityConsoleBridge`，别处不直接调 `Debug.Log`。

## 日志去了哪

| 去处 | 在哪看 |
|---|---|
| Unity 的 Console | 编辑器里 |
| 日志文件 | 编辑器菜单 Game → 日志 → 打开日志目录 |
| 内存里的最近记录 | 代码里 `GameRuntime.Logging.Recent.Lines()` 和 `.Errors()` |

日志文件每次运行一个，名字是 `log-年月日-时分秒.txt`，只留最近 5 次，单个文件最多 10 MB。目录在玩家数据目录的 `Logs` 下，Windows 上是 `%USERPROFILE%\AppData\LocalLow\<公司名>\<产品名>\Logs`。

文件开头是这次运行的信息（版本、系统、显卡等），之后一行一条：

```
12:03:45.120 F1234 E [Save] 读档失败：文件不存在
    at Game.Core.Save.SaveReader.Open()
```

依次是时间、帧号、级别字母（E、W、I、V、VV）、分类、内容；错误的调用栈缩进写在下面。搜 ` E [` 就是所有错误。

Unity 自己和第三方代码报的东西也在这个文件里，分类是 `Unity`；主线程以外没人接住的异常，分类是 `Unhandled`。

## 崩溃包

一个崩溃包是一个目录，在玩家数据目录的 `CrashReports` 下（菜单 Game → 日志 → 打开崩溃包目录），名字是 `年月日-时分秒-原因`，最多留 10 个。

| 文件 | 内容 |
|---|---|
| `info.txt` | 原因、异常的文字和调用栈、版本和机器信息 |
| `log.txt` | 出事前最近 500 行日志 |
| `Player.log` | Unity 自己那份日志的复制（编辑器里是 `Editor.log`） |
| `log-….txt` | 上次运行的日志文件（只有"上次没正常退出"的包里有） |

三种情况会写：

| 原因 | 什么时候 | 编辑器里 |
|---|---|---|
| `Exception` | 出现没人接住的异常，一次运行只写第一个 | 不自动写 |
| `UncleanExit` | 启动时发现上次运行没走到正常退出 | 不检查 |
| `Manual` | 菜单 Game → 日志 → 写一个崩溃包，或代码里 `GameRuntime.Logging.WriteCrashReport("原因")` | 运行时可用 |

写进包里的每一行都把玩家的用户目录换成了 `~`。

## 测试里

核心层的测试类继承 `CoreTestBase`，经 `Log` 打的日志就被 `Logs` 接住了：

```csharp
public class SaveTests : CoreTestBase
{
    [Test]
    public void 文件不存在时报错()
    {
        Logs.ExpectError("文件不存在");   // 声明：这条错误是预料中的

        new SaveReader().Open("没有这个文件");

        Assert.That(Logs.Messages, Is.EqualTo(new[] { "读档失败：文件不存在" }));
    }
}
```

一条测试结束时，出现过没声明的错误，或者声明了的错误没出现，这条测试都判失败。

## 它是怎么搭起来的

```
Log ─► 管线（盖戳 → 同一个错只记一次 → 补调用栈）─► 多个去处 ┬ 内存里的最近记录
                                                          ├ Unity 的 Console
                                                          ├ 日志文件
                                                          └ 盯着没人接住的异常
```

- `Log` 只是入口，它把一行交给 `Log.Output`。
- 上面这一整套由引擎层的 `LogSystem` 组装，`GameRuntime` 在启动时建它、退出时收掉它。
- 整个日志系统只有一个抽象 `ILogSink`（能接收一行日志的东西），所以零件可以任意套接。

## 要加东西时改哪里

| 要加什么 | 怎么加 |
|---|---|
| 一个新的去处（例如游戏里的调试面板） | 实现 `ILogSink`，然后 `GameRuntime.Logging.Sinks.Add(它)`。它抛了异常会被自动拿掉，并在别的去处留一条错误。 |
| 一道新的工序（例如按分类限流） | 实现 `ILogProcessor`，在 `LogSystem` 建管线的那一行里加进去。返回 false 就是拦下这一行。 |
| 换文件里一行的格式 | 实现 `ILogFormatter`，在 `LogSystem` 里换掉 `PlainTextLogFormatter`。 |
| 崩溃包里多带一个文件 | 加进 `LogSystemSettings.CrashReportAttachments`。 |
| 改保留几次、文件多大 | 改 `LogSystemSettings` 里对应的那一项。 |
