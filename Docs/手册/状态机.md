# 状态机：怎么用

## 它是什么

扁平状态机：状态是一个枚举，规则是一张"边"的表。当前状态能做什么，由它的出边决定；哪条边的条件满足了，就走哪条。没有分层，没有"状态类"。

四个类，各管一件事：

| 类 | 管什么 |
|---|---|
| `Transition` | 一条边：从哪到哪、什么条件、走的时候做什么 |
| `TransitionTableBuilder` | 装配阶段用：一条一条加边，最后建出表 |
| `TransitionTable` | 建好的表，不可变，可以给任意多个对象共用 |
| `StateMachine` | 一张表加一个当前状态 |

## 建一张表

```csharp
public enum Door : byte { Closed, Opening, Open }

public sealed class DoorContext
{
    public bool Pushed { get; set; }
    public int OpenedCount { get; set; }
}

TransitionTable<Door, DoorContext> table = new TransitionTableBuilder<Door, DoorContext>()
    .Add(Door.Closed, Door.Opening, c => c.Pushed)
    .Add(Door.Opening, Door.Open, c => true, c => c.OpenedCount++)
    .Build();
```

- 上下文是一个你自己写的类：边的条件读它，动作写它。
- 条件必须有，而且只读不改。要"无条件"就明着写 `c => true`。
- 表建出来就不能改了，上面没有加边的方法。

## 走边的规则

1. 只看当前状态的出边，按添加的先后求条件，第一条为真的执行。
2. 执行的先后：改状态 → 调动作 → 通知走边的记录者 → 向父机发消息。
3. 没有边满足：状态不变，什么都不调，返回 `false`。
4. 一步最多走一条边，不连跳；要连跳就下一步再走。

## 两种用法

**数量少的对象**（程序运行状态、一次加载流程）用 `StateMachine`：

```csharp
var machine = new StateMachine<Door, DoorContext>(table, Door.Closed);
bool moved = machine.Tick(context);
Door now = machine.State;
```

**大量同类对象**（以后的居民、作坊）直接用表：表只建一份，每个对象自己只存一个枚举。

```csharp
for (int i = 0; i < doors.Length; i++)
{
    table.Step(ref doors[i].State, doors[i].Context, doors[i].Handle);
}
```

## 大状态里套小流程：子机向父机发消息

不做分层状态机。小流程是另一台状态机，它干完了、失败了、或者需要父机做点什么，就向父机发一条消息。消息只有三类：`Finished`、`Failed`、`Request`，各带一个整数。

写法一，写在边上（推荐）：走这条边时自动发。

```csharp
TransitionTable<Load, LoadContext> childTable = new TransitionTableBuilder<Load, LoadContext>()
    .Add(Load.Reading, Load.Done, c => c.AllRead, message: new StateMachineMessage(StateMachineMessageKind.Finished))
    .Add(Load.Reading, Load.Broken, c => c.Corrupt, message: new StateMachineMessage(StateMachineMessageKind.Failed, 2))
    .Build();

var child = new StateMachine<Load, LoadContext>(childTable, Load.Reading, parent: OnChildMessage);
```

写法二，走边之外随时发：`child.Emit(StateMachineMessageKind.Request, 5);`

父机收到消息后，一般只把它记进自己的上下文，由自己的某条边的条件去读，下一次 `Tick` 时再走边：

```csharp
private void OnChildMessage(StateMachineMessage message)
{
    _parentContext.LoadFinished = message.Kind == StateMachineMessageKind.Finished;
}
```

表里有边要发消息，建状态机时却没给父机，会当场抛异常，不会等到运行中走到那条边才发现。

## 记下每条边

想知道状态机走过哪些边（以后的黑匣子要用），建表时给一个记录者：

```csharp
TransitionTable<Door, DoorContext> table = builder.Build(trace);
```

记录者实现 `ITransitionTrace`，每走一条边被通知一次：谁、从哪、到哪、原因码。原因码是加边时的 `reason` 参数，含义你自己定。"谁"是那个对象的句柄（见 `Docs/手册/句柄.md`）：`StateMachine` 构造时的 `owner`，或者 `Step` 的第三个参数。不给就是空句柄。子机发给父机的消息里，`Source` 也是这个句柄。

## 现成的例子

`Game.Core.Flow.AppFlow`（程序运行状态）就是用它搭的：转移表是一个 `AppTransition` 的列表，别人调 `Request` 申请，申请先记进上下文，每条边的条件是"有人申请去我的终点"。
