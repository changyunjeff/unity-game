# 编程规范

机器能查的规矩（缩进、大括号、命名格式）写在工程根目录的 `.editorconfig` 里，Rider 会照它提示和格式化。这份文件只写机器查不了的。两边冲突时以 `.editorconfig` 为准，然后回来改这份文件。

## 一、分层

| 层 | 程序集 | 目录 | 能引用谁 |
|---|---|---|---|
| 核心层 | `Game.Core` | `Assets/Scripts/Core` | 只有 C# 标准库。不引用 Unity。 |
| 引擎层 | `Game.Engine` | `Assets/Scripts/Engine` | 核心层、Unity。 |
| 编辑器扩展 | `Game.EngineEditor` | `Assets/Scripts/EngineEditor` | 核心层、引擎层、Unity 编辑器。只在编辑器里存在，不进打出来的包。 |
| 测试 | `Game.Core.Tests` | `Assets/Tests/Core` | 被测的那一层。 |

1. 一样东西不需要 Unity 的对象就放核心层。核心层引用 Unity 会直接编译失败，这是故意的。
2. 目录、命名空间、程序集三者对齐：`Assets/Scripts/Core/Logging` 里的代码在 `Game.Core.Logging`。
3. 核心层不读系统时钟，不用没有种子的随机数，游戏里的数值用整数。同样的输入必须得到同样的结果。
4. 引擎层的 `MonoBehaviour` 只做转接：把 Unity 的事件交给核心层，把核心层的结果画出来。规则不写在 `MonoBehaviour` 里。

## 二、命名

| 对象 | 规则 | 例子 |
|---|---|---|
| 类型、方法、属性、事件 | 首字母大写的驼峰 | `TransitionTable`、`TryStep` |
| 参数、局部变量 | 首字母小写的驼峰 | `category`、`moved` |
| 私有字段 | 下划线加首字母小写的驼峰 | `_sink`、`_edgesByFrom` |
| 常量、私有的 `static readonly` | 首字母大写的驼峰 | `Edges`、`LogFlow` |
| 接口 | `I` 开头 | `ILogSink` |
| 什么都不做的实现 | `Null` 开头 | `NullTransitionTrace` |
| 状态枚举 | 以 `State` 结尾 | `AppState` |
| 日志分类字段 | `Log` 开头 | `LogFlow` |
| 测试类 | 以 `Tests` 结尾 | `AppFlowTests` |
| 测试方法 | 一句中文，说的是行为 | `表外的申请被拒_状态不动_通知带着原因` |

1. 标识符用英文，不用拼音，不用自造的缩写。
2. 文件名等于里面主要类型的名字。一个文件一个主要类型；紧挨着它用的小类型可以放同一个文件（例如接口和它的 `Null` 实现）。
3. 指向某种东西的句柄写成 `Handle<那种东西的类型>`，例如 `Handle<Workshop>`；字段和参数用它指的东西起名（`target`、`owner`），不带 `Handle` 后缀。
4. 命令、事件的命名，等搬到它们的时候再补进这张表。

## 三、写法

1. 语言版本到 C# 9 为止，这是 Unity 6000.6 编译用的版本。
2. 访问修饰符全部写明，`private` 也写。
3. 大括号各占一行；只有一句的 `if`、`for` 也加大括号。
4. 只有一个表达式的属性和方法用 `=>`。
5. 右边一眼看得出类型时才用 `var`。
6. 公开的数据用属性，不用公开字段。例外：`readonly struct` 里的 `readonly` 字段。
7. 不用 `#region`。一个文件长到需要折叠，就该拆。
8. 每一步都会跑的代码里不用 LINQ，不产生垃圾内存。装配阶段随意。

## 四、出错要响

1. 不该发生的事发生了就抛异常，不悄悄改成一个"差不多"的值继续跑。
2. 参数不合规矩，在入口处就抛 `ArgumentException` 一类的异常。
3. 不写吞掉异常的 `catch`。只有最外层（日志的去处、宿主）可以接异常，接了必须 `Log.Error`。
4. 被拒绝的请求要让调用的人知道：返回值加通知，不静默。
5. 还没实现的地方写 `throw new NotImplementedException()`，不写一个空函数假装做完了。

## 五、日志

1. 只用 `Log.Error / Warning / Info / Verbose / VeryVerbose`。除了 `UnityConsoleBridge`，别处不直接调 `Debug.Log`。例外：编辑器扩展（`Game.EngineEditor`）在没点运行时日志系统还没起来，可以直接用 `Debug.Log`。
2. 每一级什么时候用，写在 `LogLevel` 的注释里。
3. 遍历大量数据的循环体里不打日志。
4. 日志语句不改游戏状态，不消耗随机数。

## 六、结构

1. **一个类只做一件事。** 说它是什么时要用"和"字连起来，就该拆。例：起文件名和清旧文件是 `LogFileDirectory`，一行写成什么样是 `ILogFormatter`，`FileLogSink` 只管写。
2. **依赖从构造函数传进来。** 一个类要用到的别的东西（时钟、去处、格式、目录），由建它的人给，它自己不去找，也不自己 `new` 一个具体的。这样测试里可以换成假的，不用碰全局状态。
3. **能变的地方做成接口，用组合拼起来。** 常用的三种拼法：
   - 同一个接口套同一个接口，一层加一样本事（`LogPipeline` 也是一个 `ILogSink`）。
   - 把多个合成一个（`CompositeLogSink`）。
   - 把一串小工序排成一条线，每道只做一件事，可以拦下、可以改（`ILogProcessor`）。
4. **接口在定义的当天就要有第二个实现**，`Null` 实现或测试里的替身都算，而且要真的被测试用到。做不到就先写成具体的类。
5. **参数多了就包成一个对象。** 一个函数超过四个参数，把它们收进一个数据类（`CrashReport`、`LogSystemSettings`）。
6. **不用静态的可变状态。** 只有两处例外：`Log`（打日志的入口，后面可以整个换掉）和 `GameRuntime`（唯一的装配点）。
7. **整个程序只有一个装配点：`GameRuntime`。** 贯穿运行始终的系统都在它的 `Start` 里按先后建起来，在 `Stop` 里按相反的先后收掉。别的类不自己去挂 Unity 的启动回调，也不写单例；要用这些系统，从 `GameRuntime` 拿。
8. **不可变的数据优先。** 传来传去的数据用 `readonly struct`，要改就用 `With…` 得到一份新的（`LogEntry`）。
9. **装配和运行分成两个类型。** 需要先一点点配好、之后不许再改的东西，配的时候用一个 builder，配完建出一个不可变的对象（`TransitionTableBuilder` 建出 `TransitionTable`）。这样"运行中改配置"在编译时就写不出来，不用靠运行时的标记去拦。

## 七、注释

1. 注释、文档、日志内容用中文。
2. 公开的类型和成员用 `///` 写一句它是什么。写"为什么这么做"，不写"这行代码做了什么"。
3. 临时的话不留在代码里。还没做的事用 `NotImplementedException` 标出来，不用 `// TODO`。

## 八、测试

1. 核心层每个公开的行为至少一条测试。测试名说的是行为，不是实现。
2. 测试之间互不依赖，不依赖时钟。改了全局的东西，在 `TearDown` 里还原。
3. 一块东西算做完：Unity 里编译通过，Test Runner 的 EditMode 全绿。
